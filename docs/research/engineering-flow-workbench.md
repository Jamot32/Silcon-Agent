# Engineering flow workbench: evidence, configuration and diagnosis

Research date: 2026-11-03. Primary-source web research and read-only inspection of the repository and its committed recordings; no model, synthesis, simulation or physical-design job was started. **Evidence** below names observed code, artifacts or upstream behavior. **Recommendations** are engineering inferences, not measured PPA improvements. This is an audit snapshot before the proposed workbench changes.

The strongest next increment is an inspectable physical-flow experiment: identify the exact inputs and constraints, see what failed and at which corner, compare like-for-like evidence, then start a bounded new experiment from known settings. Additional unrestricted tool parameters would provide less immediate value.

## Verified application capabilities and limits

- [EDA pins](../../eda/versions.env) and [Dockerfile](../../eda/Dockerfile) select LibreLane **3.0.16**, image digest `sha256:02d50f259d483979e126ef188a50f5b61e1d285b9d538312f280b087439b0302`, and SKY130 revision `8afc8346a57fe1ab7934ba5a6056ea8b43078e71`. The latter matches the [upstream release PDK manifest](https://github.com/librelane/librelane/blob/3.0.16/librelane/pdk_hashes.yaml). The release's [OpenROAD derivation](https://github.com/librelane/librelane/blob/3.0.16/nix/openroad.nix) names commit `dcf36133a369abc8f3c5e5738cd4d82e4903c0e0`. Current upstream docs describe concepts; new flags must be checked against this release before use. No runtime version command was run in this research.
- [PhysicalPlanner](../../backend/app/agent/physical.py) already binds mapped-synthesis measurements to source digest, top, clock, synthesis strategy and image identity. It computes an explicit die from measured mapped area/site geometry, or respects a fixed footprint. The old fixed-die limitation described in the earlier [deterministic-flow research](deterministic-flow.md) has therefore been addressed.
- [BuildConfig](../../backend/app/schemas.py) permits only `SYNTH_STRATEGY`, `FP_CORE_UTIL` and `PL_TARGET_DENSITY_PCT` at review, with six flow attempts maximum and up to five repair loops. Clock comes from the target; the planner sizes the die. [Flow validation](../../backend/app/eda/flow.py) additionally permits bounded clock/die overrides internally. These are application limits, not upstream limits.
- [Flow execution](../../backend/app/eda/flow.py) applies host-owned all-corner setup/hold/electrical policies after user/model overrides. [Parsers](../../backend/app/eda/parsers.py) return structured `signoff_checks`, `drv_ok` and violating corners; missing evidence remains unknown. The persistent `Metric` and result UI expose a smaller subset. The workbench can expose existing evidence without new EDA calls.
- [Packaging](../../backend/app/packaging.py) freezes the selected flow's RTL/tests, resolved config, raw metrics and physical outputs. It does not substitute later working files. Its ordinary manifest lacks a complete image/PDK/constraint provenance record; optional harness evidence contains additional identity. The inspected historical bundle has no SDC, SPEF, SDF or timing-report member. “Download selected design” is supported; “portable full-flow reproduction” is a stronger capability still requiring work.
- [FlowComparison](../../frontend/components/run/flow-comparison.tsx) displays planned overrides and aggregate measurements. [read_report](../../backend/app/eda/flow.py) exposes timing summary, area, power and manufacturability to the agent, bounded to 8 KiB. There is no general user-facing per-corner report inspector in the audited API.

## What primary sources imply for the product

| Primary-source evidence | Implementable implication (recommendation) |
| --- | --- |
| LibreLane preprocesses conditional/expression-based configuration into resolved values. [Configuration reference](https://librelane.readthedocs.io/en/latest/reference/configuration.html) | Distinguish **requested**, **planned**, and **resolved** settings. A planned override badge is not a full reproduction recipe. |
| In the pinned release, placement density is a percentage; if omitted, its calculation considers measured utilization and cell padding. Absolute floorplanning consumes explicit die/core bounds. [Placement source](https://github.com/librelane/librelane/blob/3.0.16/librelane/steps/openroad.py), [floorplan script](https://github.com/librelane/librelane/blob/3.0.16/librelane/scripts/openroad/floorplan.tcl) | Explain utilization as a sizing goal, density as a placement goal, and measured occupancy as evidence. Lowering utilization does not itself resize an already absolute die. In this application the planner may recompute that die, so display the actual resulting bounds. |
| OpenROAD timing-driven placement weights critical nets; routability-driven placement estimates congestion and spreads cells. Repair may resize/buffer cells, increasing area. [Global placement](https://openroad.readthedocs.io/en/latest/main/src/gpl/README.html), [resizer](https://openroad.readthedocs.io/en/latest/main/src/rsz/README.html) | Present area, timing and congestion as trade-offs. A density slider must not promise better PPA. Show estimated mapped area separately from final standard-cell area and die/core area. |
| Post-route STA uses extracted parasitics; setup and hold have separate checks. Clock constraints alone do not prove closure. [LibreLane timing guide](https://librelane.readthedocs.io/en/stable/usage/timing_closure/index.html), [timing corners](https://librelane.readthedocs.io/en/stable/usage/timing_corners.html) | Separate setup, hold, electrical checks, DRC, LVS and gate-level functional tests. Identify stage and corner. Reducing clock frequency is not a general remedy for hold failures. |
| Pinned STA emits `min.rpt`, `max.rpt`, `checks.rpt`, skew reports and positive worst-slack metrics; WNS is clamped to zero when slack is positive. [Pinned STA reporting](https://github.com/librelane/librelane/blob/3.0.16/librelane/scripts/openroad/sta/corner.tcl) | Label `1000/CLOCK_PERIOD` as configured frequency, not Fmax. Use worst slack (`__ws`) for positive margin; WNS=0 cannot distinguish small from large margin. Provide setup/hold paths and constraint warnings without running STA again. |
| Pinned aggregation uses **sum across corners** for setup/hold violation counts, **maximum** for slew/cap/fanout counts, and **minimum** for setup/hold WNS/TNS. [Metric definitions](https://github.com/librelane/librelane/blob/3.0.16/librelane/common/metrics/library.py) | Do not call every count “unique endpoints” or sum per-corner electrical counts. Show aggregation semantics and individual corners. |
| OpenSTA can inspect unconstrained paths and missing clocks/delays; a report with no paths is not proof of good timing. The pinned base SDC supports a single physical clock and creates a virtual clock when absent. [OpenSTA debugging](https://opensta.readthedocs.io/en/latest/Debugging/), [constraint checks](https://opensta.readthedocs.io/en/latest/Commands/#check_setup), [pinned base SDC](https://github.com/librelane/librelane/blob/3.0.16/librelane/scripts/base.sdc) | Add constraint coverage and physical-versus-virtual clock context. Multi-clock/CDC support requires a separate constraint model and validation, not merely another clock input field. |
| Yosys ABC maps logic to a target technology with a delay objective; that objective is not a measured routed frequency. [Yosys technology mapping](https://yosyshq.readthedocs.io/projects/yosys/en/stable/cmd/index_passes_techmap.html#abc-use-abc-for-technology-mapping) | Explain `AREA n`/`DELAY n` as synthesis strategies whose effects require measured comparison. Preserve mapped-versus-routed provenance. |
| LibreLane can retain earlier-step reports after failure and create a portable step reproducer from its configuration and input state. [Migration guide](https://librelane.readthedocs.io/en/latest/getting_started/migrants/), [pinned Step API](https://github.com/librelane/librelane/blob/3.0.16/librelane/steps/step.py) | A failed run deserves an inspector with the last completed stage and retained diagnostics. Step reruns need a validated saved state; “resume from placement” cannot safely mean replaying an arbitrary config. |

Power also needs provenance: the pinned STA script emits an unqualified `power__total` for each corner; the application's parser explicitly treats the merged value as the last reported corner. Do not claim nominal, worst-case or workload-specific power savings from it. [Pinned reporting](https://github.com/librelane/librelane/blob/3.0.16/librelane/scripts/openroad/sta/corner.tcl), [application parser](../../backend/app/eda/parsers.py).

## Concrete historical signoff discrepancy

**Observed:** `demo_recordings/uart-optimization/bundle.zip`, selected tag `flow_41725ad89a984a1f`, contains `design__max_slew_violation__count = 11` despite zero setup/hold WNS and clean DRC/LVS. Each of `nom_ss_100C_1v60`, `min_ss_100C_1v60` and `max_ss_100C_1v60` reports 11; the aggregate is 11, not 33. The audited result UI can say “Block signoff is clean” using DRC/LVS alone. This recording predates the stronger host policy described in [DECISIONS](../DECISIONS.md).

Reproduce without a tool invocation:

```python
import json, zipfile
with zipfile.ZipFile("demo_recordings/uart-optimization/bundle.zip") as bundle:
    raw = json.loads(bundle.read("raw_metrics.json"))
    assert raw["design__max_slew_violation__count"] == 11
    assert raw["timing__setup__wns"] == raw["timing__hold__wns"] == 0
```

**Recommendation:** preserve historical artifacts and show their actual electrical-check evidence. Label DRC/LVS specifically when that is all that is available. Unknown checks must never become zero/pass. The selected `counter-improvement` and `uart-repair` bundles have zero for these inspected setup/hold/electrical counts; they are useful positive fixtures.

## Prioritized implementation

1. **P0 — flow inspector and accurate selected signoff.** Select one immutable flow attempt, then show phase/status, requested/planned/resolved config availability, source identity, actual diagnostics, individual check counts and corners, and artifact availability. Recover selected replay evidence from its bundle where available. Use an immutable event ID for event lookup; model tool-call IDs can repeat. A tag-based lookup must still bind to the specified run. Partial/failed attempts must remain inspectable without acquiring another run's evidence.
2. **P1 — reuse reviewed settings with explicit scope.** “Use flow settings” should copy only the three supported review knobs, show the clock target separately, and explain that die sizing and signoff policy are recomputed. Reuse exact selected RTL when authorized; do not claim a different variant's source was reused just because its settings were copied. Display a before/after config diff and retain the six-attempt budget. Avoid an action named “Reproduce” until the complete input/environment contract is present.
3. **P1 — actionable failure evidence.** Show the first diagnostic, the failing tool/stage, the last completed physical stage, and each attempted recovery with changed values. Offer a draft follow-up such as reduce logic, adjust an explicit target, or inspect a named corner; require a new submitted run before execution. Existing deterministic recovery already distinguishes density reduction, bounded die growth, delay strategy and RTL repair; expose that reasoning before adding more recovery guesses.
4. **P1 — constraints and path reports.** Expose bounded saved setup/hold path and constraint-check reports with exact stage/corner. Provide full artifact download when retained, clearly marking excerpts as truncated. Add positive worst slack, constrained/unconstrained endpoint evidence and clock context as fields only when the actual artifact contains them.
5. **P2 — reproducibility/export and congestion evidence.** Add image identity, PDK revision, source/test/constraint hashes, selected tag and resolved-config hash to a versioned manifest. Retain a bounded allowlist of step config/state/report artifacts. A later step-reproducer feature can use LibreLane's saved-state API. Congestion inspection should use saved router reports, not infer congestion from utilization alone; OpenROAD can emit such reports. [Global routing report support](https://openroad.readthedocs.io/en/latest/main/src/grt/README.html#global-route).

Defer arbitrary Tcl/SDC execution, freeform flow-step removal, automatic signoff-policy relaxation and claims of multi-clock closure. OpenLane 2 supports custom flows and step substitution, but the application's constrained Classic-flow contract does not currently validate those workflows. [OpenLane custom flows](https://openlane2.readthedocs.io/en/latest/usage/writing_custom_flows.html).

## Offline acceptance checks

- Inspect the UART optimization recording and show 11 slew violations without changing its stored metrics or declaring a current-policy pass.
- Repeated tool-call IDs, absent finished events, failed preflight, missing metrics, malformed/nonfinite values and a selected tag with no matching metric cannot borrow another attempt's evidence.
- A requested configuration, planned configuration and resolved file that differ remain visibly distinct; a missing source stays unavailable.
- A completed bundle continues to use the selected frozen sources when later working files differ. Safe-settings reuse cannot copy signoff bypasses, arbitrary paths, unrelated die overrides or unsupported knobs.
- Parse retained fixture reports and configs only. Verify traversal/symlink/archive-member bounds and readable failure states without starting a model or EDA job.

These checks establish data integrity and usable diagnosis. Whether a suggested configuration improves PPA remains an empirical question for a separately authorized measured run.

## Implemented after this audit

The flow inspector now selects immutable event occurrences or a run-scoped physical tag, exposes separate requested/planned/applied/resolved settings, reads bounded retained reports, verifies command receipts and bundle checksums, and surfaces individual historical signoff checks. Failed calls with measurements and preflight failures remain visible. Initial build controls persist through drafts, API storage, worker execution and review; supported settings can seed an editable follow-up without automatically starting a build. Detailed per-corner path browsing, constraint-coverage analysis and portable step reproduction remain follow-on work.

## Conservative sizing policy proposal

This section is proposed policy, not an official guarantee of routability.

- Prefer the pinned tool's relative area sizing for ordinary standalone blocks, with app-owned minimum dimensions/PDN-safe geometry and a declared maximum. If deterministic explicit dimensions are needed for inspectability, first run mapped synthesis on the exact RTL/top/clock/strategy and derive an absolute plan from that evidence.
- A reasonable first explicit policy is mapped standard-cell area A, reserve1.25A, desired core utilization u=0.40, hence core area >=1.25A/u. For square aspect ratio, core side >=sqrt(area). Add the exact pinned site margins and round outward to physical site/manufacturing grid; retain current100µm application minimum until a later real-tool qualification establishes a smaller safe minimum. Headroom/minimum are declared policy values, never fabricated measured cell area. If a wrapper is to be fabricated, synthesize the wrapper+core, not only core.
- Return measured mapped area separately from requested/planned die/core dimensions, actual resolved die/core bbox, and final physical stdcell area. Missing/nonfinite/nonpositive/partial mapping area does not produce a made-up plan. Preserve generic count/area=None when only generic synthesis was requested.
- Freeze source hash, interface mapping hash, PDK revision, tool/image digest, clock and synthesis strategy with the area evidence. Changed RTL, top, clock, strategy, wrapper or library invalidates the preflight evidence. Run the same settings in physical flow.
- Current allowed50..500µm geometry is application policy. If auto plan exceeds cap, report capacity and needed dimensions; never silently clamp a too-small die. If caller supplied explicit fixed DIE_AREA, do not override it silently. Distinguish `standalone_auto`, `fixed_user`, `tt_fixed` geometry policy.
- `max_area_um2` is a final **standard-cell area target**, not a die area cap. Do not size a tiny die from this target or compare it with minimum die area. A target below mapped A is evidence of an optimization challenge, not a reason to deny all measurement or corrupt reported area. Continue only within existing budgets; retain target missed if no candidate meets it.
- For a verified geometry failure in standalone_auto, permit at most one growth attempt (e.g. minimum +25% per affected dimension or required width from actual PDN alert, rounded outward), bounded by cap and remaining physical-flow budget. Keep requested timing/functional RTL/test contract unchanged. Fixed tile/user geometry fails with an actionable capacity/constraint message; do not auto-upgrade purchased/selected tile allocation. Growth does not establish shuttle fit.

Suggested APIs after freeze: `read_mapped_synthesis(...) -> MappedSynthesisEvidence`; `plan_floorplan(evidence, policy, fixed_geometry=None) -> FloorplanPlan`; `classify_flow_failure(stage, alerts, execution) -> FlowFailure`; `plan_recovery(failure, plan, remaining_budget) -> RetryPlan|None`. Keep these deterministic and small; do not expose PDK file paths to model-controlled JSON.

## Addendum: optional deterministic test-quality mutation (source lookup only)

Pinned Yosys0.62 has both [connect](https://github.com/YosysHQ/yosys/blob/v0.62/passes/cmds/connect.cc#L46) and [mutate](https://github.com/YosysHQ/yosys/blob/v0.62/passes/sat/mutate.cc#L737). No command was executed to test the proposed recipe during the frozen cohort.

**Use connect for a top-output clamp.** Exact supported form is `connect [-nomap] [-nounset] -set <lhs-expr> <rhs-expr> [selection]`. It disconnects existing LHS drivers by default, then adds the requested connection. `-nounset` would retain old drivers and is inappropriate. It requires a module without RTLIL processes and a single selected/active module. Default alias mapping resolves names to their primary driver; `-nomap` disables that behavior, which is essential for an output that aliases an input/internal signal. [Implementation](https://github.com/YosysHQ/yosys/blob/v0.62/passes/cmds/connect.cc#L29) detaches matching cell output connections and assignment LHS bits; it does not remove or rename public ports. This is a structural netlist mutation, not a source-text rewrite.

The simplest width-safe mutation is the whole selected output port, e.g. `connect -nomap -set result 0`. [SigSpec::parse_rhs](https://github.com/YosysHQ/yosys/blob/v0.62/kernel/rtlil.cc#L5937) explicitly expands `0` to the full LHS width, and expands `~0` to full-width ones. `1'b0` is suitable for a one-bit LHS but is **not automatically widened** by this parser when an entire bus is selected. A bit LHS such as `result[0]` is accepted, but [SigSpec::parse](https://github.com/YosysHQ/yosys/blob/v0.62/kernel/rtlil.cc#L5893) interprets it as a zero-based internal wire offset rather than applying the Verilog declaration start_offset/upto convention. Whole-port clamps avoid accidentally selecting the wrong declared bit of nonzero/ascending vectors. Validate the selected object against parsed actual top output metadata; exclude inputs/inouts, use validated simple identifiers, and preserve top identity and complete port widths/directions.

Proposed post-freeze recipe, using generated script file and trusted validated names/paths rather than shell interpolation:

```yosys
read_verilog <same validated source files>
synth -top TOP -noabc
select -module TOP
connect -nomap -set OUTPUT_PORT 0
select -clear
check -assert
write_verilog <isolated mutant.v>
```

Every flag above is in pinned help/source. [synth -noabc](https://github.com/YosysHQ/yosys/blob/v0.62/techlibs/common/synth.cc#L64) runs ordinary generic synthesis without ABC; its script performs proc, memory mapping and default generic techmap, no Liberty/sky130 technology mapping. [select -module / -clear](https://github.com/YosysHQ/yosys/blob/v0.62/passes/cmds/select.cc#L1162) sets one module scope then restores whole-design selection. [check -assert](https://github.com/YosysHQ/yosys/blob/v0.62/passes/cmds/check.cc#L37) rejects conflicting drivers, used undriven wires and combinational loops. A structural check failure invalidates the mutant and never counts as a killed functional mutant.

An even smaller `hierarchy -top TOP; proc; ...connect...; write_verilog` pipeline is source-supported for ordinary small logic, but memory/other unresolved-cell cases need more care. `proc` is mandatory because connect refuses process-bearing modules; [proc help](https://github.com/YosysHQ/yosys/blob/v0.62/passes/proc/proc.cc#L32) states conversion to muxes, FFs and latches. Full generic synth avoids many export/simulation support questions and is more predictable than an ad hoc incomplete techmap sequence. It still needs actual qualification before product use.

[write_verilog help](https://github.com/YosysHQ/yosys/blob/v0.62/backends/verilog/verilog_backend.cc#L2474) emits a netlist and by default converts internal cells into Verilog expressions. Default renaming affects internal dollar-prefixed names, not public names. [Module emission](https://github.com/YosysHQ/yosys/blob/v0.62/backends/verilog/verilog_backend.cc#L2424) enumerates module->ports and dumps their declarations, preserving the public interface. Do **not** add `-noexpr` for this simple cocotb route: it leaves cell instances and may require [simcells.v](https://github.com/YosysHQ/yosys/blob/v0.62/techlibs/common/simcells.v#L22) for low-level generic cells and [simlib.v](https://github.com/YosysHQ/yosys/blob/v0.62/techlibs/common/simlib.v#L22) for higher-level cells. simlib's memory note requires memory_collect for separate memory ports. A Liberty-mapped netlist instead requires matching technology simulation models and often power-pin handling; avoid mapped/physical netlists for this optional test-quality probe. User blackboxes/macros/unresolved modules are unsupported unless their genuine simulation models already belong to the baseline test setup. Default write_verilog is not a universal semantic-equivalence guarantee: source warns about exporting unlowered RTLIL processes.

**mutate exists but is less suitable here.** Exact application form is `mutate -mode const0 -module M -cell C -port P -portbit B` (const1/inv also supported). [Application code](https://github.com/YosysHQ/yosys/blob/v0.62/passes/sat/mutate.cc#L945) requires the module, cell, cell-port and valid portbit. `-wire/-wirebit/-src` are candidate filtering/documentation fields, explicitly ignored during application, so they do not directly target a top output wire. [const0 semantics](https://github.com/YosysHQ/yosys/blob/v0.62/passes/sat/mutate.cc#L673) replace a selected cell input bit with zero, or detach a cell output bit and drive the old net with zero. Optional `-ctrl` adds control ports through hierarchy and would alter the cocotb interface; omit it. `mutate -list N -seed N` supports seeded candidate enumeration, but choosing unstable internal cells and proving an observable change adds complexity unnecessary for an output-clamp smoke check.

**Qualification and honest outcome rules.** After freeze, first export the unmodified generic netlist using the same transform and rerun unchanged tests. If transformed-original tests fail, classify export/test setup as unsupported; do not attribute failure of the transformed mutant to test quality. Check unchanged top port signatures and test hashes. Then clamp one deterministically selected output port in a separate isolated directory, compile and run the same tests. Count only an actual functional expectation/assertion failure from an executed test as `killed`; generation, lint, synthesis, structural check, compile, unresolved-module, import/API, simulator launch, unknown-value conversion, cancellation or harness timeout failure is `invalid/inconclusive`, not killed. Preserve artifacts and report surviving, equivalent/not-applicable, and invalid mutants separately. Additional mutation simulations need explicit small bounds and must never overwrite baseline source/tests or become fabricated user verification evidence.

Zero clamping does not guarantee a non-equivalent mutant: that output may legitimately remain0 under the contract, or tests may not excite it. A killed mutant proves detection of this one change; a survivor alone does not prove weak tests without evidence the mutant changes required behavior.

# Reference-first neutral control — research only

This fixture tests a single small, hand-specified synchronous block. On a rising edge, active-low reset or `clear` sets a 3-bit accumulator to zero; otherwise, if `enable` is high, `amount` is added and the result saturates at 7. A disabled cycle holds its value. The Python reference model is written first; the unittest checks a hand-worked literal sequence. The host then concatenates the same model and four manually written cocotb tests into one ordinary test module for both RTL versions. The tests check both the model against literal answers and the simulator output against the model after the update settles.

The deliberate mutant wraps at 3 bits instead of saturating. With the pinned local image `sha256:9b62eb4f8e873591f6925c3aaf1f7cf459e848e867809a9068d48d49025f3cc8`, mutant first failed exactly `test_saturates_instead_of_wrapping` (3 passed, 1 failed; `DUT: expected 7, got 1`); the good implementation passed all 4. Both Docker processes returned zero without timing out: the retained runtime JSON and simulator XML, not process exit alone, report the test outcome. Actual inputs, host receipts, output XML, logs, and hash-bound report remain in `evidence-001/` (report SHA-256 `e9bf221a2b55aa3677d1232aa1174796e4a0485a91f9468c98e71e4091f2c042`). The initial model unittest failed with a missing module; after implementing the model it passed. A second qualification retained its own separately executed model unittest receipt (exit 0, no timeout, model and test source hashes unchanged), then reproduced the 4/4 good and 3/4 mutant outcomes; its report SHA-256 is `59bb75190197443ac18e950bf5fb3069ad81bc9643b344205a6d3990499a5ca0`. Attempt 001 remains unchanged.

Reproduce with a fresh evidence directory inside this folder, from the isolated checkout root:

```sh
python3 -B research/reference_first/test_qualifier.py
SA_REFERENCE_EVIDENCE="$PWD/research/reference_first/evidence-003" python3 -B research/reference_first/qualify.py
```

The qualifier invokes the image's existing `runtime.py sim` directly with network disabled and a read-only container root/input. It first runs and records the model unittest, then verifies the image ID, unchanged assembled inputs, host exit/timeout, the four distinct expected XML testcase names, strict integer runtime counts, and the same expected mutant testcase and failure message in XML and runtime JSON. The synthetic qualifier controls cover duplicate or unexpected names, boolean and non-integer counts, mismatched failure messages, skipped cases, and malformed XML. It is not a production `ToolRunner` or orchestrator integration and does not qualify path admission, generated test policy, delivery snapshots, packaging, or adversarial test code. Its tests use one manually stepped clock and known values; multi-clock, combinational, asynchronous-reset, unknown input, tri-state, timing-dependent and generalized port contracts are not covered. Four directed tests and one mutant cannot establish behavior for arbitrary user specifications; model and model-derived tests may share mistakes. No model/API calls, DEV accuracy claim, reference independence claim, signoff or held-out claim follows.

Cocotb 2.0.1's [timing model](https://docs.cocotb.org/en/v2.0.1/timing_model.html) describes the `ReadOnly` sampling phase used here; its [runner API](https://docs.cocotb.org/en/v2.0.1/runner.html) is experimental. This fixture validates the observed behavior of the pinned image only.
